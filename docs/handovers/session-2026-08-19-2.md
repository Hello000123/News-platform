## Key Decisions Made

| Decision | Rationale | Alternatives Considered |
|----------|-----------|------------------------|
| Create a separate plain-language file instead of simplifying the technical handover in place. | Both audiences retain the level of detail they need, and the verified technical runbook is not weakened. | Replacing the technical version would remove commands and engineering context needed during incidents and releases. |
| Use exact current button and tab labels. | A low-knowledge reader can follow the live interface without translating engineering terminology. | Generic instructions such as “manage the account” were rejected as too ambiguous. |
| Tell non-technical readers when to stop and escalate. | Database restore, secret rotation, deployment, code recovery, and permanent deletion can cause serious damage. | Providing copy-and-run technical commands in the beginner guide would create unnecessary operational risk. |
| Put human editorial verification before publication. | AI-generated text can be wrong even when automated validation succeeds. | Treating AI output as publication-ready was rejected. |
