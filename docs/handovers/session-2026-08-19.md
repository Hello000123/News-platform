## Key Decisions Made

| Decision | Rationale | Alternatives Considered |
|----------|-----------|------------------------|
| Use `docs/WEBSITE_HANDOVER.md` as the human-facing offboarding document. | It already contains the business, operational, security, and technical detail a successor needs and was audited against the current checkout. | Replacing it with the shorter session template would discard important company-transfer context. |
| Treat `News-platform/` as canonical. | It is the most current checkout, is on `main`, contains the latest commits, and has the active handover work. | `News-platform-latest/` and `AI-Agent-News-Review-Rewrite/` are divergent dirty checkouts and cannot safely be assumed to match production. |
| Do not rotate `AUTH_SECRET` until a password-pepper migration plan exists. | Production currently falls back to `AUTH_SECRET` because no separate `PASSWORD_PEPPER` secret is configured; an uncoordinated rotation would invalidate existing password proofs. | Immediate secret rotation was rejected as unsafe without establishing the stable pepper or resetting all account passwords. |
| Keep all live and paid operations out of this documentation session. | The user requested a handover, not a production change, and several actions require company ownership and budget authority. | Deploying, migrating, sending test email, or calling AI providers would expand scope and could alter production state. |
