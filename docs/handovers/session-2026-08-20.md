## Key Decisions Made

| Decision | Rationale | Alternatives Considered |
|----------|-----------|------------------------|
| Create `WEBSITE_HANDOVER_DETAILED.md` instead of extending the original in place. | The original remains a concise verified technical summary, while the requested maximum-detail version serves deep onboarding and incidents. | Replacing the original would make quick orientation harder and blur its existing verification scope. |
| Preserve the 19 August production date inside a document created across midnight. | Deployment IDs, counts, feed time, and secret names were verified on 19 August and must not be presented as 20 August observations. | Updating the date without new production queries would create false precision. |
| Use current source, migrations, routes, and configuration as evidence for expansion. | The user requested length, but accuracy remains more important than filler or invented organizational process. | Adding unsupported vendor, legal, or ownership claims was rejected. |
| Put dangerous commands behind prerequisites, approval records, and stop conditions. | Deployment, D1 restoration, secret rotation, remote employee creation, and deletion can materially damage production. | A bare command list would be faster but unsafe for offboarding. |
