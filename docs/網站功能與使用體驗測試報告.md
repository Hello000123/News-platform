# 網站功能與使用體驗測試報告

測試日期：2026-08-05（香港時間）
範圍：只評估功能與使用體驗；不評估安全性、效能或成本。

## 測試方式

- 以一般讀者、已登入編輯／管理員的操作路徑測試。
- 檢查桌面版與 390 × 844 手機版。
- AI 審稿與改寫使用本機模擬服務，完整操作介面流程；沒有以真實 AI 供應商的輸出品質作結論。
- 以正式建置再次檢查主要閱讀與錯誤頁，避免把開發模式問題誤列為產品問題。

## 已完成並已驗證

### 公開新聞網站

- 首頁可正常載入主稿、精選報道、最新短訊及頁尾導覽；「精選報道」和「最新短訊」錨點可正確捲動至對應段落。
- 首頁主稿的文字與圖片連結皆可開啟正常的新聞詳情頁。
- 正常文章頁可顯示標題、摘要、來源、日期、原文連結、正文、重點及延伸報道；返回首頁的連結可用。
- 桌面與手機版均沒有明顯的版面溢出，主稿、文章頁及新聞管線在手機寬度下仍可閱讀與操作。

### 編輯工作區

- 可在 DeepSeek V4 Pro 與 Grok 4.5 間切換模型，並清楚提示換模型後要重新審稿。
- 空白草稿按「Review Draft」會把焦點帶回輸入框並顯示明確提示。
- 已完成實測：評分結果、六項分類分數、建議／優點、通過門檻、手動觸發 AI 改寫、直接改寫、再次改寫、精簡選項與文字指示。
- 改寫後可複製結果；按「Edit draft myself」再修改草稿後，舊評分會標記為過期、改寫按鈕會停用，避免誤用舊結果。
- 模擬 AI 服務失敗時，畫面會顯示易理解的錯誤、供應商／階段資訊及「Retry Rewrite」按鈕。
- 「Start New Draft」可清空目前草稿、評分與改寫結果。

### 新聞管線與管理介面

- 新聞管線可載入稿件、切換 New／Rewritten／Approved／Discarded／All 篩選，並在空資料時顯示對應說明。
- 點選一篇管線稿件後可閱讀來源內容與改寫入口。
- 管理面板可載入帳戶摘要、帳戶審批、客戶帳戶、員工帳戶及新聞來源分頁；目前資料狀態會正確顯示「沒有待處理申請」。

### 程式層面的驗證

- `npm run typecheck` 通過。
- 正式版 `npm run build` 通過。
- 首頁／頁面相關測試通過；新聞管線的 8 個測試在可啟動本機暫存服務的環境中全部通過。

## 已發現的問題

| 優先度 | 問題 | 使用者影響 | 實測結果 |
| --- | --- | --- | --- |
| P1 | 不存在的新聞網址顯示空白頁 | 讀者點到舊連結、打錯網址或文章下架時，看不到任何說明或返回入口。 | `/news/not-a-real-article` 在開發版與正式版皆回傳 404，但瀏覽器畫面是全白；預期的「找不到這篇報道」介面沒有顯示。正常文章頁則可正常顯示。 |
| P1 | 新聞管線出現重複稿件 | 編輯需重複判斷同一則內容，容易造成重覆改寫或誤判稿量。 | New 清單中「天文台一度發出黃色暴雨警告信號 廣泛地區曾受大雨影響」以同一來源 `oncc` 連續出現 3 次。 |
| P1 | 新聞管線混入非新聞／促銷內容 | 編輯清單被優惠券、折扣碼與商品促銷稀釋，降低「新聞管線」的可用性。 | New 清單可見多篇 WIRED coupon／promo code 項目，例如 Nomad、Wayfair、Target 等優惠碼。 |
| P2 | 公開閱讀體驗的語言不一致 | 面向繁體中文讀者時，首屏標題和摘要為英文、正文卻是繁中，閱讀感受不連貫。 | 首頁主稿與文章頁的標題／摘要為英文，重點與內文則為繁中；頁尾同時標示「TRADITIONAL CHINESE」。 |
| P2 | 手機版管線選稿後沒有帶使用者到詳情 | 點選稿件後只見卡片變成選取狀態，詳情面板在列表下方，使用者需自行繼續捲動才能發現來源內容與改寫按鈕。 | 在 390px 寬度點選第一篇稿件後，詳情不是自動聚焦或捲至可見位置。 |

## 尚未完成或尚未驗證

### 尚未驗證的既有功能

- 未以真實 AI 模型驗證審稿品質、改寫品質與真實供應商錯誤訊息；本次只驗證本機模擬回應下的介面流程。
- 未送出帳戶申請，也未執行批准、拒絕、移除帳戶等會改變帳戶資料的動作。
- 未執行「Import scraper JSON」、「Rewrite top 5 in Chinese」、管線稿件改寫、批准或捨棄等會改變既有新聞資料的動作。

### 公開讀者端仍欠缺的瀏覽功能

- 沒有關鍵字搜尋、來源／分類篩選、日期篩選或可瀏覽的完整文章列表；公開首頁目前主要依賴精選區、短訊區與個別文章連結。
- `/news` 會返回首頁，沒有獨立的文章索引／歸檔頁；對想找舊報道的讀者不夠直接。
- 尚未見公開的分享、收藏或相關主題探索入口；若目標是完整新聞閱讀網站，這些仍是待補的讀者功能。

## 建議處理順序

1. 先修正不存在文章的 404 空白頁，確保至少提供「找不到文章」與返回首頁的行動入口。
2. 修正管線去重，並在進入編輯清單前排除優惠券、促銷碼與明顯非新聞內容。
3. 統一公開頁面的語言策略；若定位為繁體中文新聞站，至少要讓標題、摘要、內文與介面語言一致。
4. 改善手機版選稿後的焦點與捲動行為，讓詳情和下一步操作立即可見。
5. 視產品定位補上公開搜尋、篩選與文章索引，降低讀者只能依賴首頁精選內容找文章的限制。
